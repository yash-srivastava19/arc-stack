# arc vs. git benchmark

This directory holds the harness behind the [Benchmarks](https://arc-pr-docs.netlify.app/benchmarks) page. It runs everyday stacked-branch tasks twice, once with arc and once with the shortest correct sequence an expert would type in plain git, then checks the result and times both.

## Run it

You need git 2.30 or later, Python 3.11 or later, and [uv](https://docs.astral.sh/uv/).

```bash
uv venv bench/.venv
VIRTUAL_ENV=$PWD/bench/.venv uv pip install --compile-bytecode .   # or: "arc-prs==<version>"
cd bench
python3 oracle_selftest.py                       # the checker must pass this first
python3 run_scripted.py --out results/mine.jsonl
python3 report.py --version <version>            # tables from results/scripted-<version>.jsonl
```

To benchmark a different arc, install it into another venv and set `BENCH_VENV` to that venv's path.

| File | What it does |
|---|---|
| `scenarios.py` | Each scenario: the starting repository, the expected end state, the arc commands, and the git commands. |
| `lib.py` | Builds repositories, plays the teammate, and holds the checker. |
| `run_scripted.py` | Runs both command sequences, checks them, and times them. |
| `oracle_selftest.py` | Proves the checker passes correct end states and fails broken ones. |
| `report.py` | Prints the tables on the docs page from `results/`. |
| `run_agent.py` | Optional: gives the same tasks to an AI agent through headless `claude -p`. It uses your Claude account's usage. |

## How a run works

- **Fresh repositories.** Every run builds a new repository and a bare `origin.git` in a temporary directory outside this repo. A second clone of origin plays the teammate who pushes to `main`, merges PRs, or pushes to your branch.
- **Isolation.** All `GIT_*` variables are removed. git uses `bench/gitconfig`, with hooks off and system config ignored.
- **Deterministic commits.** Author, committer, and dates are fixed, so the same steps produce the same commit IDs.
- **No GitHub.** origin is a local bare repository. `bin/gh` is a stub that reports you're logged in and rejects everything else.
- **Timing.** The arc and git sequences run alternately, 15 times each by default, each on a fresh repository. Building the repository isn't timed.
- **Counting.** Commands are lines that start with `git`, `arc`, or `gh`. git processes are counted with `GIT_TRACE2_EVENT`, including the ones arc starts.

## How a result is checked

A checker reads the repository after the commands finish and compares it with the expected end state. It reads git state, plus `.arc/state.json` for arc. Exit codes don't count. A run passes only if every check passes.

| Check | What it verifies |
|---|---|
| `O0_trunk` | `main` on origin has the expected files. |
| `O1_trees` | Each branch has exactly the expected files and contents. |
| `O2_chain` | Each branch sits directly on the branch below it, and the bottom branch on `main` from origin. |
| `O3_commits` | Each branch has the expected number of commits, and its diff from the branch below matches. |
| `O4_pushed` | Each branch on origin points at the same commit as the local branch. |
| `O5_clean` | No rebase or merge is in progress, HEAD is on a branch, and the working tree has no unexpected changes. |
| `O6_gone` | Branches the task removes are gone, locally and on origin. |
| `O8_rollback` | For the abort task, every branch is back at its starting commit. |
| `O9_wip_kept` | Uncommitted changes the task says to keep are unchanged. |
| `O10_arc_state` | For arc, `.arc/state.json` lists the real stack, in order. |

`oracle_selftest.py` runs the checker against the git sequence's end state for every scenario, which must pass, and against 11 deliberately broken end states, which must fail. The broken states are a lost commit, an extra commit, a stale parent, an unpushed branch, a rebase left in progress, a wrong conflict resolution, a partial rollback, a deleted branch left on origin, a teammate's commit overwritten, lost uncommitted work, and a stale branch in `.arc/state.json`.

## Assumptions

- **The git side is an expert.** It uses git 2.38+ features such as `rebase --update-refs`, `--onto`, `--autostash`, and `--force-with-lease`.
- **The arc side follows arc's documentation**, including the hints arc prints.
- **Small, clean stacks.** 5 branches with one commit each. S11 repeats three tasks with 3 commits per branch.
- **Local only.** PRs aren't opened, retargeted, or landed on GitHub. With the `gh` stub, arc detects merged branches from git history alone.
- **No network in the timings.** arc skips its PyPI version check when its output isn't a terminal.

## Scenarios

Each scenario starts from a pushed stack `b1 -> b2 -> b3 -> b4 -> b5` on `main`, with HEAD on `b5`, unless it says otherwise. These are the exact sequences the harness runs, generated by `python3 report.py --scenarios`.

### S1: Build a stack and push it

main is up to date. Build a stack of 5 branches named b1, b2, b3, b4, b5, each built on the previous one (b1 on main), each with exactly one commit: b1 adds file f1.txt containing exactly the line 'b1 v1'; b2 adds file f2.txt containing exactly the line 'b2 v1'; b3 adds file f3.txt containing exactly the line 'b3 v1'; b4 adds file f4.txt containing exactly the line 'b4 v1'; b5 adds file f5.txt containing exactly the line 'b5 v1'. Push every branch to origin.

**arc**

```bash
arc init --base main -q
arc new b1 -q
printf 'b1 v1\n' > f1.txt
git add f1.txt
git commit -q -m 'feat: b1'
arc new b2 -q
printf 'b2 v1\n' > f2.txt
git add f2.txt
git commit -q -m 'feat: b2'
arc new b3 -q
printf 'b3 v1\n' > f3.txt
git add f3.txt
git commit -q -m 'feat: b3'
arc new b4 -q
printf 'b4 v1\n' > f4.txt
git add f4.txt
git commit -q -m 'feat: b4'
arc new b5 -q
printf 'b5 v1\n' > f5.txt
git add f5.txt
git commit -q -m 'feat: b5'
arc push -q
```

**git**

```bash
git checkout -q -b b1
printf 'b1 v1\n' > f1.txt
git add f1.txt
git commit -q -m 'feat: b1'
git checkout -q -b b2
printf 'b2 v1\n' > f2.txt
git add f2.txt
git commit -q -m 'feat: b2'
git checkout -q -b b3
printf 'b3 v1\n' > f3.txt
git add f3.txt
git commit -q -m 'feat: b3'
git checkout -q -b b4
printf 'b4 v1\n' > f4.txt
git add f4.txt
git commit -q -m 'feat: b4'
git checkout -q -b b5
printf 'b5 v1\n' > f5.txt
git add f5.txt
git commit -q -m 'feat: b5'
git push -q origin b1 b2 b3 b4 b5
```

### S2: Amend a mid-stack branch

A reviewer asked for a change on b2: f2.txt must contain exactly the line 'b2 v2'. Fold the fix into b2's existing commit (b2 must stay a single commit), make sure every branch above b2 includes the change, and update origin.

**arc**

```bash
git checkout -q b2
printf 'b2 v2\n' > f2.txt
git add f2.txt
arc edit -q
```

**git**

```bash
printf 'b2 v2\n' > f2.txt
git add f2.txt
git commit -q --fixup=b2
GIT_SEQUENCE_EDITOR=: git rebase -q -i --autosquash --update-refs main
git push -q --force-with-lease origin b2 b3 b4 b5
```

### S3: Trunk moved: sync

Someone merged new work into main on origin. Bring the whole stack up to date with origin's main (b1 directly on top of it) and update origin.

**arc**

```bash
arc sync -q
arc push -q
```

**git**

```bash
git fetch -q
git rebase -q --update-refs origin/main
git push -q --force-with-lease origin b1 b2 b3 b4 b5
```

### S4: Sync with a conflict: resolve

Someone merged a change into main on origin. Bring the whole stack up to date with origin's main (b1 directly on top of it) and update origin. If conf.txt conflicts, resolve it so the file contains exactly two lines: 'from-b3' then 'from-main'.

**arc**

```bash
arc sync -q || true
printf 'from-b3\nfrom-main\n' > conf.txt
git add conf.txt
arc rebase --continue -q
arc push -q
```

**git**

```bash
git fetch -q
git rebase -q --update-refs origin/main || true
printf 'from-b3\nfrom-main\n' > conf.txt
git add conf.txt
git rebase --continue
git push -q --force-with-lease origin b1 b2 b3 b4 b5
```

### S5: Sync with a conflict: abort

Try to bring the stack up to date with origin's main. If that hits any conflict, do NOT resolve it: back out completely so every local branch and everything on origin is exactly as it was before you started, with a clean working tree and nothing in progress.

**arc**

```bash
arc sync -q || true
arc rebase --abort -q
```

**git**

```bash
git fetch -q
git rebase -q --update-refs origin/main || true
git rebase --abort
```

### S6: Bottom branch squash-merged

b1's pull request was just squash-merged into main on origin (the merge also deleted b1 on origin). Remove b1 locally, put the rest of the stack (b2 and up) directly on top of origin's new main without re-applying b1's change, and update origin.

**arc**

```bash
arc sync -q
arc push -q
```

**git**

```bash
git fetch -q --prune
git rebase -q --update-refs --onto origin/main b1 b5
git branch -q -D b1
git push -q --force-with-lease origin b2 b3 b4 b5
```

### S7: Drop a middle branch

The idea in b3 was abandoned. Remove b3 from the stack entirely (its change must not appear in any branch), so b4 sits directly on b2. Delete b3 locally and on origin, and update origin.

**arc**

```bash
arc drop b3 --force -q
arc push -q
git branch -q -D b3
git push -q origin --delete b3
```

**git**

```bash
git rebase -q --update-refs --onto b2 b3 b5
git branch -q -D b3
git push -q --force-with-lease origin b4 b5 :b3
```

### S9: Review fix as a new commit

A reviewer asked for a change on b2. Add a new commit on b2 that creates f2_fix.txt containing exactly the line 'review fix' (b2 then has two commits). Make sure every branch above b2 includes it, and update origin.

**arc**

```bash
git checkout -q b2
printf 'review fix\n' > f2_fix.txt
git add f2_fix.txt
git commit -q -m 'fix: review'
arc rebase --upstack -q
arc push -q
```

**git**

```bash
git checkout -q b2
printf 'review fix\n' > f2_fix.txt
git add f2_fix.txt
git commit -q -m 'fix: review'
git rebase -q --update-refs b2 b5
git push -q --force-with-lease origin b2 b3 b4 b5
```

### S10: Sync with uncommitted changes

You have uncommitted edits in f5.txt on b5 that are not ready to commit. Someone merged new work into main on origin. Bring the whole stack up to date with origin's main (b1 directly on top of it) and update origin. Keep your edits to f5.txt exactly as they are, uncommitted.

**arc**

```bash

arc push -q
```

**git**


### S14: Teammate pushed to a stack branch

A teammate pushed an extra commit to b2 on origin (it adds t2.txt). Separately, someone merged new work into main on origin. Bring the stack up to date so that b2 includes your teammate's commit and b1 sits directly on origin's main, then update origin without losing your teammate's work.

**arc**

```bash
arc sync -q
arc push -q
```

**git**

```bash
git fetch -q
git checkout -q b2
git merge -q --ff-only origin/b2
git rebase -q --update-refs b2 b5
git rebase -q --update-refs origin/main b5
git push -q --force-with-lease origin b1 b2 b3 b4 b5
```

### S15: Conflict during a mid-stack amend

b3's commit changes conf.txt. A reviewer asked that b2's commit also set conf.txt to exactly the line 'from-b2'. Fold this into b2's existing commit (b2 stays one commit), carry the change up the stack, and update origin. When b3 conflicts on conf.txt, resolve it so conf.txt contains exactly two lines: 'from-b2' then 'from-b3'.

**arc**

```bash
git checkout -q b2
printf 'from-b2\n' > conf.txt
git add conf.txt
arc edit -q || true
printf 'from-b2\nfrom-b3\n' > conf.txt
git add conf.txt
arc edit --continue -q
```

**git**

```bash
git checkout -q b2
printf 'from-b2\n' > conf.txt
git add conf.txt
git commit -q --amend --no-edit
git rebase -q --update-refs --onto b2 b2@{1} b5 || true
printf 'from-b2\nfrom-b3\n' > conf.txt
git add conf.txt
git rebase --continue
git push -q --force-with-lease origin b2 b3 b4 b5
```

### S16: Insert a branch mid-stack

A reviewer asked you to split out a preparatory change. Create a new branch bX between b2 and b3, with one commit that adds fx.txt containing exactly the line 'bx v1'. b3 must then sit directly on bX. Push bX and update origin.

**arc**

arc has no command for this. Use the git sequence.

**git**

```bash
git checkout -q -b bX b2
printf 'bx v1\n' > fx.txt
git add fx.txt
git commit -q -m 'feat: bX'
git rebase -q --update-refs --onto bX b2 b5
git push -q --force-with-lease origin bX b3 b4 b5
```
